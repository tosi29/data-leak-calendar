# 情報漏えいカレンダー

国内の企業・団体が公表した情報漏えいと、その可能性を出典付きで整理する静的サイトです。

[公開カレンダー](https://tosi29.github.io/data-leak-calendar/)

## 使い方

- **公表カレンダー**：日別の掲載事案数を表示。日付を選ぶと一覧を絞り込めます。
- **検索**：組織・サービス名、情報の種類、公表月、経緯・原因、漏えい状況、関連ベンダーで絞り込めます。検索条件はURLで共有できます。
- **月別の積み上げグラフ**：案件ごとの公表対象規模を表示。人・件・アカウントを切り替えられ、検索条件と表示年に連動します。ホバーで規模を確認し、クリックで案件詳細へ移動できます。
- **事案一覧**：各行を開くと対象情報、規模、原因、関連ベンダー、出典、続報を確認できます。掲載データはJSONでダウンロードできます。

## 掲載・集計基準

2026年5月1日以降の公表を対象に、原則として「組織と事案の組み合わせ」を1件として記録します。同一事案の続報は既存記録へ反映し、追加計上しません。委託先事故に関する利用組織の公表はそれぞれ記録するため、掲載件数は独立した攻撃の回数ではありません。

漏えい確認・可能性・調査中・閲覧可能・紛失・漏えい否定・同意のない提供を区別します。確認待ち候補は掲載・集計から除外します。全事案の網羅を保証するものではなく、掲載なしは発生なしを意味しません。

グラフは**公表された対象規模の参考合計**です。単位を混ぜず、数値不明や同単位の内訳が複数ある案件、漏えい否定の案件は除外します。「約」「最大」や流出の可能性を含み、同じ人・情報の組織間の重複は除去できません。最新の判明規模を掲載公表日に割り当てており、当時判明していた件数の履歴ではありません。

詳しい日付・状態・件数の扱いは[データの追加・更新と形式](docs/data-guide.md)を参照してください。調査範囲や未確認事項は[調査記録の索引](docs/research/README.md)にまとめています。

## ローカルで動かす

Node.js 22以降と、プレビュー用にPython 3を使用します。`npm install` は不要です。

```sh
npm test
npm run build
npm run preview
```

[localhost:4173](http://localhost:4173) を開きます。ビルド時にデータを検証します。検証だけを実行する場合は `npm run check` を使用します。

## 構成とデータ更新

| 場所 | 内容 |
| --- | --- |
| `public/` | HTML・CSS・ブラウザー用JavaScript |
| `data/incidents/` | 1事案1JSONの掲載データ |
| `data/meta.json` | 収集開始日・最終確認日など |
| `data/candidates.json` | 確認待ちの候補 |
| `docs/` | データ仕様・調査記録 |
| `scripts/`・`tests/` | 検証・ビルド・テスト |
| `dist/` | ビルド生成物 |

更新時は公表資料の本文と既存記録を照合し、出典・確認日を残します。続報は同じJSONへ追記し、日付を更新してテスト・ビルドを実行します。詳細は[更新手順](docs/data-guide.md)を参照してください。

調査履歴は個別の調査文書と監査データへ記録し、READMEには日次の作業ログや件数を追記しません。

## 公開

`main` へのpushで [GitHub Actions](.github/workflows/pages.yml) が検証・ビルド・GitHub Pagesへの公開を実行します。PRでは検証とビルドのみです。

初回はリポジトリの Settings → Pages → Source を **GitHub Actions** に設定します。公開対象は `dist/` です。相対URLを使用しているため、サブパスでも動作します。外部ライブラリ・APIキー・分析用Cookieは不要です。
